# ALIGN02 customer Catalogue handoff

Owner: the existing Innovdia-Tech/savt-cks-go frontend team. Local backend
checkpoint only; no frontend repository, publication or customer screen changed.
This supersedes ALIGN01's optional classification wording for **new** products.

New master products require exact Barcode, Item description and an active
Category/Subcategory pair. CKS Department maps to shopping Category; its
Subdepartment maps to Subcategory. Actual reference IDs drive browse membership.
Raw Division and the deeper CKS `category` remain internal source details.
Approved shopping labels may change on the reference without rewriting raw
source descriptions or product identity.

## Exact customer contract

Continue using `X-CKS-Product-Contract: cks-v1`, the existing trusted Savt session
and `X-CKS-Assignment-Context`. Product detail response shape is unchanged:
`description` is the Item description, `barcode` preserves exact text, and
`category`/`subcategory` contain `{id,name}` or truthful historical nulls.
Use those approved names in the detail display. Preserve existing image, price,
availability and purchase controls. A null classification needs a fallback
display; it must not reject the entire response or invent an Other category.

- Category directory: `GET /customer/outlets/:outletId/categories`.
- New child directory:
  `GET /customer/outlets/:outletId/categories/:categoryId/subcategories`.
  Rows have exactly `{id,categoryId,code,name}`; the directory includes active
  children of an active parent. Pagination/private response metadata follows
  the existing Category contract.
- Product drill-down: existing products route with `categoryId`, plus optional
  `subcategoryId`. Supplying a child requires its parent. Child-only requests
  return `CUSTOMER_SUBCATEGORY_PARENT_REQUIRED`; mismatched/inactive pairs return
  no products. Filtering uses persisted IDs, not raw codes or display names.

[serializer-fixtures.json](serializer-fixtures.json) was generated by the real
services and serializers against migrated disposable PostgreSQL. It includes
mapped detail, historical-null detail, directories, correct browse membership
and wrong-parent empty results. IDs, session bindings, outlet and data are
synthetic; do not send fixture IDs to a live environment. Trusted context and
readiness collaborators are mocked, while persistence and predicates are real.

Product/outlet-product IDs, image behavior, sellingPriceMinor, cart/quote/order
identity and frozen receipt item identification retain their current contract.
No Category/Subcategory metadata is added to receipts. Receipt branding remains
separate work.
