# MERCH-HOME01 implementation plan

**Goal:** Complete the user's Phase 1 Home merchandising specification using the existing catalogue, carousel and native trust boundaries.

**Spec:** User-provided MERCH-HOME01 request (preserved in the parent workspace's attachment); no redesign, publication or changes to payment, receipt, assignment or Browse authority.

**Architecture:** HQ advertisements expose a closed `action` union. Home uses the existing customer advertisements endpoint and a separate `featured=true` catalogue query capped at 24. Product actions resolve a master ID through the assigned outlet catalogue before opening existing detail. Native external links use a new strict message alongside existing bridges.

**Ancestry:** Web starts at accepted FE-FINAL01 `b3a0f05eb2527f0cc5829743f9141f8398883b90`, a descendant of `9b090470c3a4f7b6f5ac8374ec2852e68438ad98`. Native starts at accepted FE-RECEIPT02 `000810ab54039f0639e0aaf3d36fbdadf3f95a7b`, a descendant of `faa3642368ee45ab98db51cf1805c6d4f95222b0`. Original branches remain untouched.

## Constraints and review focus

- Local only: no push, PR, CI, merge or deployment; at most two useful lanes.
- Preserve session, assigned-outlet price/stock, receipt and payment-return contracts.
- Advertisement request failure and zero results hide banners; no synthetic production fallback.
- Reject invalid destination shapes, unsafe URLs and unavailable assigned-outlet targets.
- Clear scoped merchandising on assignment/session changes; ignore late stale responses.
- A swipe must not click the banner; NONE has no action semantics.
- Featured visibility is 6, 12, 18, 24; zero hides section; Browse remains complete.
